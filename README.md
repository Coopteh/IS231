# Тестирование по белому ящику (White-Box Testing)

## Определения

### Тестирование по белому ящику
**Тестирование по белому ящику** (white-box testing) — это метод тестирования программного обеспечения, при котором тестировщик имеет доступ к внутренней структуре, исходному коду и логике работы приложения. Тестовые случаи проектируются на основе анализа кода для проверки всех возможных путей выполнения, условий и операторов. [[9]]

### Покрытие операторов (Statement Coverage)
**Покрытие операторов** — это метрика тестирования, которая измеряет процент исполняемых операторов исходного кода, выполненных хотя бы один раз в ходе тестирования. Формула: `(выполненные операторы / всего операторов) × 100%`. [[6]]

### Покрытие условий/решений (Condition/Decision Coverage)
**Покрытие условий** требует, чтобы каждое булево подвыражение в условном операторе было оценено как `true` и `false` хотя бы один раз. **Покрытие решений** (ветвей) требует выполнения всех возможных исходов каждого условного оператора (if/else). [[13]][[19]]

**Цель:** Выполнить каждый оператор кода хотя бы один раз.

**Преимущества:**
- Простота реализации и измерения
- Выявление мёртвого кода и недостижимых ветвей
- Базовый уровень качества тестов

**Недостатки:**
- Не гарантирует проверку всех логических условий
- Может пропустить ошибки в сложных условиях [[5]]
