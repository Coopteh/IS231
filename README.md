Определения
1. Тестирование по белому ящику (White-box Testing)
    Это метод тестирования программного обеспечения, при котором тестировщик имеет доступ к внутренней структуре, архитектуре и коду приложения. Тестирование основывается на знании того, как работает система изнутри. Основная цель — проверить логические пути, условия, циклы и структуру данных, чтобы убедиться, что внутренний поток операций выполняется согласно спецификации, и выявить скрытые ошибки, недоступные при тестировании «черного ящика».
2. Покрытие операторов (Statement Coverage)
    Это метрика и критерий тестирования, который требует, чтобы каждая исполняемая строка кода (оператор) в программе была выполнена хотя бы один раз в ходе тестирования. Если оператор не был затронут ни одним тестом, покрытие считается неполным. Это самый базовый уровень структурного покрытия.
3. Покрытие условий (решений) (Condition/Decision Coverage)
Это более строгий критерий, чем покрытие операторов. Он требует выполнения двух условий:
    3.1 Покрытие решений: Каждое управляющее решение (например, оператор if, case) должно принять все возможные исходы (как истину True, так и ложь False) хотя бы по одному разу.
    3.2 Покрытие условий: Каждое логическое подусловие (атомарное условие) внутри составного выражения должно также принять значения True и False хотя бы по одному разу.

МЕТОДЫ ТЕСТИРОВАНИЯ ПО БЕЛОМУ ЯЩИКУ

1. Метод покрытия операторов (Statement Coverage)
    Суть метода:
        Цель состоит в том, чтобы составить минимальный набор тестовых данных, который заставит программу выполнить каждую строку кода минимум один раз.
    Как применяется:
        Строится граф потока управления (Control Flow Graph) программы.
        Определяются все узлы (операторы).
        Подбираются тесты, проходящие через все узлы.
2. Метод покрытия условий (Condition Coverage)
    Суть метода:
        Цель — убедиться, что каждое атомарное логическое условие внутри составного выражения приняло все возможные значения (True и False) хотя бы по одному разу.
    Как применяется:
        Выделяются все простые условия в составных выражениях.
        Создаются тесты так, чтобы каждое из этих условий было и истинным, и ложным.
    Плюсы:
        Глубже проверяет логику, чем покрытие операторов.
        Выявляет ошибки в отдельных частях сложных условий.
    Минусы:
        Не гарантирует покрытие всех ветвей решения (Decision Coverage). Теоретически можно покрыть все условия, но не проверить все комбинации их влияния на итоговое решение (хотя на практике часто пересекается с покрытием решений).
        Не проверяет взаимодействие условий друг с другом.
3. Метод комбинаторного покрытия условий (Multiple Condition Coverage)
    Суть метода:
        Это самый строгий и трудоемкий метод. Он требует проверки всех возможных комбинаций значений всех условий в одном решении. Также известен как «Покрытие всех условий».
    Как применяется:
        Для каждого составного условия строится таблица истинности.
        Создаются тестовые наборы для каждой строки таблицы истинности (каждой комбинации).
    Плюсы:
        Наивысшая надежность обнаружения ошибок в логических связках (AND, OR).
        Автоматически включает в себя покрытие операторов, покрытие решений и покрытие условий.
    Минусы:
        Экспоненциальный рост количества тестов. Если в условии 5 параметров, потребуется 2^5 = 32 теста только для одной строки if.
        Высокая стоимость поддержки и выполнения.
