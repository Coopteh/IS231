# IS231
Задачи для группы ИС-231
Практические работы по теме «Работа с issues на GitHub.com» для IT-студентов
Ниже представлена подборка практических заданий разного уровня сложности, которые помогут студентам освоить работу с GitHub Issues в образовательном контексте.
🔹 Базовый уровень (знакомство с интерфейсом)
Задание 1: «Создание первого issue»
Цель: Научиться создавать и оформлять задачи.
Инструкция:
Создать форк учебного репозитория или личный тестовый репозиторий.
Создать issue с заголовком и описанием по шаблону:
12345
Добавить метки: bug, enhancement, documentation.
Назначить исполнителя (себя или одногруппника).
Критерии оценки:
✅ Чёткое описание проблемы
✅ Использованы хотя бы 2 метки
✅ Указан приоритет или milestone
🔹 Средний уровень (командная работа)
Задание 2: «Жизненный цикл задачи»
Цель: Отработать полный цикл работы с issue.
Сценарий:
Разделиться на пары: «Заказчик» и «Разработчик».
Заказчик создаёт issue с описанием фичи/бага.
Разработчик:
Комментирует issue с вопросами/уточнениями
Создаёт ветку, решает задачу
Создаёт PR и ссылается на issue: Closes #123
После мёрджа — заказчик закрывает issue с комментарием.
Дополнительно:
Использовать @упоминания для коммуникации
Прикрепить скриншоты или логи к комментарию
Использовать чек-листы в описании issue: - [ ] Протестировано
Задание 3: «Шаблоны и автоматизация»
Цель: Настроить стандарты оформления задач.
Задача:
Создать файлы шаблонов в .github/ISSUE_TEMPLATE/:
bug_report.md
feature_request.md
Протестировать: создать issue через UI и убедиться, что шаблон подгрузился.
(Опционально) Добавить конфигурацию config.yml для управления типами issue.
🔹 Продвинутый уровень (проектная деятельность)
Задание 4: «Управление мини-проектом через Projects»
Цель: Интегрировать issues в Kanban-доску.
Инструкция:
Создать GitHub Project (классический или новый).
Добавить колонки: Backlog, In Progress, Review, Done.
Создать 5–7 issues для учебного проекта (например, «Калькулятор», «To-Do List»).
Назначить метки, приоритеты, исполнителей.
Перемещать карточки по мере выполнения задач.
Настроить автоматизацию: при закрытии PR задача переходит в Done.
Задание 5: «Code Review через issues»
Цель: Использовать issues для обсуждения архитектуры.
Сценарий:
Перед началом кодирования создать issue с заголовком [RFC] Предложение по архитектуре.
Описать вариант решения, приложить диаграмму/псевдокод.
Одногруппники комментируют, предлагают правки.
После согласования — создать задачу на реализацию и ссылаться на RFC-issue.
🎯 Идеи для мини-проектов
Проект
Примеры issues
Веб-калькулятор
#1 Добавить поддержку скобок, #2 Исправить округление, #3 UI: тёмная тема
Telegram-бот
#1 Подключить API погоды, #2 Обработать ошибку таймаута, #3 Документация команд
