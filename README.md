# Тестирование по белому ящику (White Box Testing)

## Определения

### Тестирование по белому ящику
**Тестирование по белому ящику** (White Box Testing) — это метод тестирования программного обеспечения, при котором тестировщик имеет полный доступ к внутренней структуре, исходному коду и логике приложения. В отличие от тестирования по черному ящику, здесь проверяется не только функциональность, но и корректность внутренних путей выполнения, циклов, условий и структур данных. Этот метод часто применяется разработчиками на этапе модульного (Unit) тестирования.

### Покрытие операторов (Statement Coverage)
**Покрытие операторов** — это метрика тестирования, которая измеряет процент выполненных исполняемых строк кода (операторов). Если тестовый набор достигает 100% покрытия операторов, это означает, что каждая строка кода в программе была выполнена хотя бы один раз в ходе тестирования. Это минимально необходимый уровень проверки кода.

### Покрытие условий (Decision/Condition Coverage)
**Покрытие условий** (также известное как покрытие решений) — это метрика тестирования, которая требует, чтобы каждое логическое условие (булево выражение) в коде приняло все возможные исходы (истина `True` и ложь `False`) хотя бы один раз. Это гарантирует, что проверены все ветви логики (например, оба пути в конструкции `if-else`).

## Методы тестирования по белому ящику

1. Метод покрытия операторов (Statement Coverage)
Суть метода:
Цель метода — убедиться, что каждая исполняемая строка кода (оператор) в программе была выполнена хотя бы один раз во время тестирования. Это базовый уровень тестирования кода.
Алгоритм применения:
Проанализировать исходный код и выделить все исполняемые операторы (присваивания, вызовы функций, выводы данных).
Составить тестовые случаи так, чтобы поток выполнения программы прошел через каждую строку.
Игнорировать объявления переменных и комментарии (они не считаются исполняемыми операторами).
Пример:
python
1234
def check_value(x):
    if x > 0:           # Оператор 1 (условие)
        print("Pos")    # Оператор 2
    print("End")        # Оператор 3
Тест 1: x = 5. Выполняются операторы 1, 2 и 3. Покрытие = 100%.
Тест 2: x = -5. Выполняются операторы 1 и 3. Оператор 2 пропускается.
Для 100% покрытия: Нужен минимум один тест, где x > 0.
Преимущества:
Простота измерения и автоматизации.
Позволяет выявить «мертвый код» (строки, которые никогда не выполняются).
Недостатки:
Не гарантирует проверку логики ветвлений. Можно выполнить все строки, но не проверить случай, когда условие ложно (например, если код внутри if содержит ошибку, но сам if выполняется).
2. Метод покрытия условий/решений (Decision/Branch Coverage)
Суть метода:
Более строгий метод, чем покрытие операторов. Требует, чтобы каждое логическое решение (ветвление) в коде приняло все возможные исходы (True и False) хотя бы один раз. Проверяются не просто строки, а переходы между ними (ветви графа потока управления).
Алгоритм применения:
Выявить все точки принятия решений (if, while, for, switch, case).
Для каждого решения спроектировать минимум два теста: один, где условие истинно, и один, где условие ложно.
Убедиться, что все выходы из узлов решения покрыты тестами.
Пример:
python
1234
if (A > 10):            # Решение 1
    do_action_A()       # Ветвь True
else:
    do_action_B()       # Ветвь False
Тест 1: A = 15 (Проверяет ветвь True).
Тест 2: A = 5 (Проверяет ветвь False).
Результат: Покрытие решений = 100%.
Преимущества:
Гарантирует проверку всех путей ветвления логики.
Находит ошибки, когда код работает только при одном исходе условия.
Включает в себя покрытие операторов (если покрыты все ветви, покрыты и все строки).
Недостатки:
Не проверяет внутреннюю структуру сложных условий. Например, в условии if (A > 0 and B > 0) метод потребует проверить только общий результат (Истина/Ложь), но не проверит все комбинации A и B по отдельности.
3. Метод комбинаторного покрытия условий (Multiple Condition Coverage)
Суть метода:
Самый полный и строгий метод. Требует проверки всех возможных комбинаций истинности элементарных условий внутри каждого сложного логического выражения.
Алгоритм применения:
Найти все составные условия (например, содержащие AND, OR).
Выделить элементарные подусловия (атомарные условия).
Составить таблицу истинности для каждого составного условия.
Создать тесты для каждой строки таблицы истинности (каждой комбинации).
Пример:
python
12
if (X > 0) and (Y > 0):  # Составное условие
    process()
Элементарные условия: C1 = (X > 0), C2 = (Y > 0).
Возможные комбинации (2^2 = 4 теста):
C1=True, C2=True (X=1, Y=1) -> Результат True
C1=True, C2=False (X=1, Y=-1) -> Результат False
C1=False, C2=True (X=-1, Y=1) -> Результат False
C1=False, C2=False (X=-1, Y=-1) -> Результат False
Преимущества:
Максимальная вероятность обнаружения логических ошибок внутри сложных выражений.
Выявляет ошибки, зависящие от взаимодействия нескольких переменных.
Недостатки:
Комбинаторный взрыв: Количество тестов растет экспоненциально (2^N, где N — количество условий). Для условия с 10 переменными потребуется 1024 теста только для одной строки кода.
Высокая трудоемкость и стоимость поддержки таких тестов.
